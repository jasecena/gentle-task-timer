# Life Timer — setup checklist

The concrete path from this working tree to a build on your iPhone, with the
decisions already made. Work top to bottom; it is resumable.

[SETUP_CHECKLIST.md](SETUP_CHECKLIST.md) is the generic template to copy into
the next project. [DEPLOYMENT.md](DEPLOYMENT.md) is the reference manual and
troubleshooting guide.

**Repository visibility: public**, so GitHub Actions macOS minutes are free.
Everything below assumes that.

## Decisions already made

Settled and reflected in the code — you do not need to re-think these.

| Question                          | Answer for Life Timer                                                            |
| --------------------------------- | -------------------------------------------------------------------------------- |
| Capabilities needed               | **None** for v0.1. Add Background Modes → Audio only when background alerts land |
| Push Notifications                | **No.** Local notifications need no capability                                   |
| Location / Microphone / HealthKit | **No.** The app is entirely offline                                              |
| Privacy usage descriptions        | **None.** Nothing is accessed that requires one                                  |
| Certificates / profiles           | **Skip.** Cloud managed signing creates them on the runner                       |
| Where the bundle id lives         | `app.config.ts`, driven by `IOS_BUNDLE_IDENTIFIER`                               |
| `ios/` directory                  | Generated by `expo prebuild` — gitignored, never hand-edit                       |

> **Capabilities are not a one-way door.** You can tick more on later at
> Identifiers → your App ID → Save, and cloud-managed signing picks up the
> regenerated profile on the next build. Just remember a capability must match
> in **two** places: the App ID in the portal _and_ the entitlements in
> `app.config.ts`. Only _removing_ a shipped capability is awkward.

## Phase 0 — Prepare to go public

Everything here is local, and none of it needs Apple.

- [ ] **Set your git identity.** It is currently unset, and your email lands in
      every public commit. GitHub's noreply address avoids publishing it:

```bash
git config user.name  "Your Name"
git config user.email "<id>+<username>@users.noreply.github.com"
```

Find your exact noreply address at GitHub → Settings → Emails. Use `--global`
instead if you want it everywhere.

- [ ] **Confirm the LICENSE credits you.** It said "650 Industries, Inc. (aka
      Expo)" — inherited from the project template — and is now
      `Copyright (c) 2026 Jason`. Add your surname or preferred attribution.

- [ ] **Choose your bundle identifier** and put it in the local `.env`
      (gitignored, already created with your Team ID in it):

```bash
# edit .env
IOS_BUNDLE_IDENTIFIER=com.<yourname>.lifetimer
```

- [ ] **Replace the app icon.** `assets/icon.png` is the Expo placeholder. It is
      already the right shape (1024×1024, RGB, no alpha — which is what Apple
      requires), so a straight swap works.

- [ ] **Verify the tree is clean and everything passes:**

```bash
npm run verify                                    # 86 tests, lint, types, format
git status --short                                # nothing credential-shaped
git check-ignore -v .env && echo ".env safely ignored"
```

- [ ] **Make the first commit.** The staged index is stale from the project
      scaffold, so stage everything fresh:

```bash
git add -A
git commit -m "Initial commit: Life Timer with Mac-free iOS release pipeline"
```

> Nothing has ever been committed, so there is no history to audit — the best
> possible position from which to publish. Keep it that way: never commit a
> credential, because going private later does **not** un-publish anything.

## Phase 3 — App Store Connect

- [ ] Create the app record (Apps → **+** → New App). Must exist _before_ the
      first upload, or it fails with "no suitable application record was found"

```
Platform:          iOS
Name:              Life Timer
Bundle ID:         the one from Phase 2
SKU:               life-timer
Primary language:  English (Australia)
```

> **Get SKU and Bundle ID right first time — they are the only fields here you
> cannot change.**
>
> | Field            | Changeable later?                                                                                                   |
> | ---------------- | ------------------------------------------------------------------------------------------------------------------- |
> | App name         | Yes, but needs a new version submission once live                                                                   |
> | Description      | Yes, freely before first submission                                                                                 |
> | Promotional text | Yes, any time, no new version required                                                                              |
> | Primary language | Awkward — effectively locked once the app is live                                                                   |
> | **SKU**          | **No.** Permanent once the record exists. Internal-only, so nobody sees it — but pick something you will not regret |
> | **Bundle ID**    | **No.** Locked as soon as a build is uploaded against it                                                            |
>
> If you get one of the permanent two wrong, the fix is deleting the app record
> and starting over — possible only before a build has been accepted.
>
> The GitHub repository description and topics, by contrast, are editable any
> time from the repo homepage.

- [ ] Create the API key — Users and Access → Integrations → App Store Connect
      API → **Team Keys** → **+**

```
Name:  github-actions-ci
Role:  App Manager     ← Developer cannot upload builds; Admin is more than CI needs
```

- [ ] Download the `.p8` (**one download only**) and record:

```
Key ID        10 characters
Issuer ID     UUID from the TOP of the Keys page — team-wide, not per-key
```

> Confusing Issuer ID with Key ID causes most first-run 401s. Different shapes:
> one is a UUID, the other is 10 characters.

```bash

wl-copy < AuthKey_XXXXXXXXXX.p8                      # Wayland
```

## Phase 7 — Device testing

- [ ] Install TestFlight on your iPhone
- [ ] App Store Connect → Life Timer → TestFlight → Internal Testing → add
      yourself, then accept the invite and install

Test what this app actually does:

- [ ] Start a 2-minute timer; confirm it counts down correctly
- [ ] Pause, wait a minute, resume — elapsed time must exclude the pause
- [ ] **Background the app mid-run for 5+ minutes, then reopen.** It must show
      the correct phase and remaining time, not a frozen countdown. This is the
      single most important behaviour to confirm on real hardware, and the one
      thing no test on Linux can prove
- [ ] Lock the screen mid-run, reopen — same expectation
- [ ] Screen stays awake while running, sleeps normally when paused or idle
- [ ] Airplane mode: identical behaviour, since nothing is online
- [ ] Battery over a realistic 30-minute session

> Known gap in v0.1: alerts are **vibration only, foreground only**. No sounds,
> no local notifications yet — so a phase change while backgrounded will not
> notify you. Tracked in the README roadmap.

## If you ever switch to private

- Re-add `${{ runner.temp }}/export/*.ipa` to the artifact `path:` in
  `ios-release.yml` if you want the binary
- Delete the `codeql` job from `security.yml`, or buy GitHub Advanced Security —
  it fails on private repos without it
- Secret scanning and push protection stop working
- Environments and their protection rules need GitHub Pro on private repos —
  verify the `ios-release` protections still apply
- Actions minutes become billable (~2,000/month free, macOS at 10×, so roughly
  8–13 releases). Consider turning the smoke test back off
